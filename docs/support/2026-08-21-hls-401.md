# Support report — HLS media playlist returns 401 (§5)

Prepared for the organisers per §5 of the integration reference. **Not yet sent** — for Het to
review and submit.

---

**Subject:** HLS live path returns 401 on the media playlist (`/live/stream/<id>/main_stream.m3u8`)

**Camera id:** `10` (`10 char-chowk-road-2-junagadh`). Reproduced identically on ids `1` and `5`.

**Exact URLs**

1. `https://live.corp8.cloud/live/stream/10/index.m3u8` → **200 OK**
2. `https://live.corp8.cloud/live/stream/10/main_stream.m3u8` → **401**

Step 2 is the master playlist's own relative reference, resolved as any HLS client would.

**Client and version**

- `curl 8.7.1`
- `ffprobe` / FFmpeg `8.1.2`
- User-Agent: `DrishtiNet-Sentinel2026/0.1 (Gujarat Police Innovation Challenge participant; hetpatelsk@gmail.com)`

**UTC timestamp:** 2026-08-21T16:35:19Z (22:05 IST). First observed 2026-08-21T16:12Z.

**Client log**

Master playlist fetches correctly:

```
$ curl -sSL -A "<UA>" https://live.corp8.cloud/live/stream/10/index.m3u8
HTTP 200, content-type: application/vnd.apple.mpegurl, 238 bytes

#EXTM3U
#EXT-X-VERSION:3
#EXT-X-INDEPENDENT-SEGMENTS

#EXT-X-STREAM-INF:BANDWIDTH=3564480,AVERAGE-BANDWIDTH=2966597,CODECS="avc1.640028",RESOLUTION=1920x1080,FRAME-RATE=25.000
main_stream.m3u8
```

Its referenced media playlist does not:

```
$ curl -sSL -A "<UA>" https://live.corp8.cloud/live/stream/10/main_stream.m3u8
HTTP 401, content-type: application/json

{"status":"error","error":"authentication error"}
```

FFmpeg fails the same way against the documented entry point:

```
$ ffprobe -v error -user_agent "<UA>" -i https://live.corp8.cloud/live/stream/10/index.m3u8
https://live.corp8.cloud/live/stream/10/index.m3u8: Server returned 401 Unauthorized (authorization failed)
```

**Additional observation**

At 2026-08-21T16:12Z the master playlist advertised the variant as
`main_stream.m3u8?session=88ec7c28-27a3-4201-af7e-d79925db4a5d`. Requesting that URL also returned
401. By 16:35Z the master no longer emitted a `session` parameter at all (238 bytes, stable across
repeated requests). Both forms return 401 on the media playlist.

Retried with a cookie jar and a `Referer` of the master playlist, in case the session is
cookie-bound; the result was unchanged.

**Also unreachable from our network**

```
rtsp://live.corp8.cloud:8554   connection timed out (closed/filtered)
http://live.corp8.cloud:8889   connection timed out (closed/filtered)
https://live.corp8.cloud:443   reachable
```

This may be a restriction on our side rather than yours — it is reported only because §3 lists HLS
as the fallback for exactly this situation, and that fallback is the path returning 401.

**What we need**

Whether the HLS path requires a credential, registration, or IP allow-listing we have missed, and if
so how to obtain it. We have not attempted to bypass the authentication and will not.
